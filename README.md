# معرض الزبيدي — نظام إدارة المعرض (v1.2.0)

نظام داخلي لإدارة معرض سيارات بالبيع النقدي والتقسيط: السيارات والمشترون والبائعون والكفلاء، المبيعات والأقساط والتحصيل، المستندات القانونية، وواتساب والتنبيهات. الأدوات الأساسية:

- لوحة تحكم: قيمة المخزون، المتاح/المحجوز/المباع، الأقساط المستحقة، المتأخرات، التحصيلات اليوم/الشهر، المصروفات، والوساطة ومستحقات البائعين.
- السيارات: حالة جديد/مستعمل، صور حتى 5 صور، متاحة/محجوزة/مباعة، والمشتري عند البيع.
- الأقساط: أيام التأخير، قيمة المتأخر، أكثر من دفعة للقسط، إيصال تحصيل تلقائي، وكشف حساب العميل.
- ملف مستندات البيع: العقد، سند الأمر، الكمبيالات، وكشف الأقساط.
- بحث موحد عن العميل/البائع/السيارة/رقم البيع.
- رقم بيع موحد موجود في النظام ويرتبط بالمستندات والأقساط.
- زر نسخ احتياطي لقاعدة البيانات.
- صفحة مصروفات بسيطة لإدخال المصروفات وعرضها.
- إيصال استلام السيارة للمشتري من المبيعات أو ملف المشتري: بيانات السيارة والمشتري وخانات استلام وتوقيع وطباعة/PDF.
- واتساب والتنبيهات: إعدادات الإرسال، قوالب الرسائل، التذكيرات وسجلها؛ المزوّد الافتراضي يجهز روابط wa.me دون إرسال تلقائي.

## التشغيل

1. ثبّت Node.js 22 LTS أو أحدث متوافق مع better-sqlite3 12.
2. من مجلد المشروع:
   - `npm install`
   - `npm --prefix server install`
   - `npm --prefix client install`
3. شغّل:
   - `npm run dev`
4. افتح واجهة Vite على العنوان الذي يظهر في الطرفية.

قاعدة البيانات تُنشأ داخل `server/data/showroom.sqlite`.

## الاختبارات وجودة الكود

```bash
npm run test        # اختبارات الخادم

npm run check:deploy # فحص إعدادات النشر والتخزين والأسرار
npm run check:all    # check + check:deploy + build + test + test:ui ← بوابة الجودة الكاملة
```

> **حالة الأرقام:** آخر تشغيل كامل موثّق هو **355 اختبارًا ناجحًا (317 خادم + 38 واجهة) بتاريخ 2026-09-30**.
> بعد ذلك عُدّلت وحدات التحصيل والدورة الحياتية والصلاحيات (10 أكتوبر) ثم شُدّد الأمان وأُضيفت 10 اختبارات
> (`auth-hardening` و`permissions-passwords`). **شغّل `npm run check:all` على جهازك واعتمد الرقم الذي يظهر لك**؛
> لا تعتمد الأرقام القديمة. اختبارات `auth-hardening` تحتاج Node 22 (تستخدم `node:sqlite` لاختبار أول تشغيل).

## المصادقة والنشر

**لا توجد كلمة مرور افتراضية.** عند أول تشغيل بلا إعدادات دخول ينشئ النظام مديرًا (`admin`) بكلمة مرور
عشوائية، تظهر مرة واحدة في نافذة التشغيل وتُحفظ في `server/data/FIRST-RUN-ADMIN.txt`.
سجّل الدخول بها، غيّرها من صفحة «المستخدمون والصلاحيات»، ثم احذف الملف.

- **بديل صريح:** اضبط `SHOWROOM_AUTH_USER` و`SHOWROOM_AUTH_PASS` (خارج Git) لحساب مدير طوارئ دائم.
  هذا أيضًا مخرجك لو نسيت كلمة مرور المدير الوحيد.
- **الأدوار:** ADMIN / ACCOUNTANT / SALES / VIEWER. النسخة الاحتياطية وسجل الحركات للمدير والمحاسب فقط؛
  الاسترجاع وإدارة المستخدمين للمدير فقط.
- **حد محاولات الدخول:** 10 محاولات فاشلة لكل عنوان خلال 10 دقائق ثم `429` (`SHOWROOM_LOGIN_MAX_FAILED`).
- **الشبكة المحلية:** يسمع الخادم على كل واجهات الجهاز، ويطبع عناوين الشبكة عند التشغيل لفتحه من أجهزة
  المعرض الأخرى. الاتصال داخل الشبكة عبر HTTP؛ لا تعرّض المنفذ للإنترنت بلا HTTPS (راجع `DEPLOY.md`).
- **روابط مشاركة المستندات:** موقّعة بسر عشوائي محفوظ في `server/data/.share-secret`، صالحة 7 أيام.
  لإبطال كل الروابط الصادرة احذف الملف وأعد التشغيل.
- للعملاء البرمجيين `SHOWROOM_API_TOKEN` عبر `X-API-Token` أو `Authorization: Bearer`؛ لا ترسل الرمز في URL.
- فحص `/api/health` وحده عام. تفاصيل CORS والوكيل والتشغيل في `DEPLOY.md`.

المعاينة فقط: `SHOWROOM_DEMO_MODE=1` مع `NODE_ENV=development` تفتح نسخة تجريبية وتستخدم
**`showroom-demo.sqlite` منفصلة دائمًا**. لا تدخل بيانات حقيقية أو توكن واتساب حقيقي فيها.

المراجعات والحدود: `SECURITY-REVIEW.md` و`QA-REPORT.md` و`HARDENING-CHANGES-AR.md`.

## النشر على Render
ملف `render.yaml` مُعدّ للإنتاج بخطة `starter` مدفوعة وقرص دائم 5GB لحفظ قاعدة SQLite والنسخ الاحتياطية بين عمليات النشر. راجع الرسوم في حساب Render قبل إنشاء أو مزامنة Blueprint، وراجع `DEPLOY.md` لخطوات حفظ البيانات واستعادتها.

يمكن استخدام Render Free للمعاينة فقط بشرط عدم إدخال بيانات حقيقية؛ تخزينه مؤقت وقد تختفي قاعدة SQLite عند إعادة التشغيل أو النشر. لا تغيّر إعداد الإنتاج إلى Free.

## هيكلة المشروع

Modular Monolith: الخادم مقسم إلى قاعدة بيانات وmigrations وخدمات وroutes وmiddleware، والواجهة إلى App وpages وcomponents وطبقة API. التفاصيل وقواعد إضافة الوحدات في `ARCHITECTURE.md`.



## WhatsApp Cloud API — الإرسال التلقائي

المشروع يدعم الآن `LINK` المجاني لفتح wa.me يدويًا، و`CLOUD` للإرسال التلقائي عبر WhatsApp Business Cloud API. لتفعيل الإرسال التلقائي: اختر CLOUD من إعدادات واتساب، ثم أدخل Phone Number ID وPermanent Token وأسماء قوالب Meta المعتمدة. خارج نافذة خدمة العميل يجب أن تبدأ الرسائل التجارية بقالب معتمد وفق سياسة WhatsApp Business. يمكن ضبط ترتيب متغيرات كل قالب من إعدادات واتساب، مثل `customer,sale,amount,link`.
